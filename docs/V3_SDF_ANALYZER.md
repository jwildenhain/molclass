# MolClass v3 SDF Analyzer

The v3 analyzer is the Java-only replacement for `sdfcheck.pl` and the definition
file generated by the legacy PHP/Perl upload path.

## CLI

```bash
./gradlew analyzeV3Sdf \
  -PimportArgs='analyze --sdf /absolute/input.sdf --output /absolute/analysis.json'
```

The command rejects unknown or incomplete options. Paths with spaces retain their
argument boundary through Gradle's command-line tokenizer.

Exit codes:

| Code | Meaning |
| --- | --- |
| `0` | Analysis completed and the output was atomically replaced. |
| `2` | CLI, path, or configured-limit error. |
| `3` | SDF decoding, chemistry parsing infrastructure, disk, or output failure. |

## Resource and parsing contract

- Input is strict UTF-8.
- The default maximum file size is 2 GiB.
- One SDF record is retained at a time, with a default 16 MiB record limit.
- Every `$$$$` delimiter closes a record.
- A non-empty final record without `$$$$` is analyzed and a warning is emitted.
- An empty, oversized, unparsable, or atom-free record is recorded as malformed and
  does not stop later records.
- Property names are trimmed only at their outer whitespace and remain
  case-sensitive.
- Repeated tags in one record are reported and cannot become identifiers.
- Distinct values are held in a temporary file-backed H2 table. SHA-256 narrows the
  lookup, and the full value is compared before equality is accepted, so hash
  collisions do not merge distinct values.
- The temporary distinct-value database is deleted on normal completion or failure.

## Identifier contract

A property is eligible only when it is present, non-blank, and distinct in every
chemically valid record and is not repeated within any record. Exact property
`Identifiers` has first priority, followed by the configured exact-name list, then
shorter values and property name for deterministic tie-breaking.

The output always sets `identifierConfirmationRequired` to `true`. Auto-selection is
a proposal, not permission to start import.

## Type inference

All non-blank values participate. Promotion is:

```text
INT -> BIGINT -> DECIMAL -> DOUBLE -> CHAR/VARCHAR -> TEXT
```

Leading-zero integer-like strings are treated as text so import cannot destroy
identifier formatting. Exact decimals are retained up to `DECIMAL(65,30)`;
scientific notation or wider numeric values promote to `DOUBLE`. Fixed-width text up
to 255 characters becomes `CHAR`, varying text up to 2,048 characters becomes
`VARCHAR`, and larger text becomes `TEXT` with overflow-storage recommendation.

The analyzer proposes types only. The import manifest and property registry resolve
new columns and safe widening before any molecule transaction starts.

## Durable worker

`V3SdfWorker` is the only process that executes queued `SDF_ANALYZE` jobs. It uses
the database advisory lock `molclass_v3_sdf_worker`, so two worker processes cannot
analyze/import concurrently. Every claimed job receives a lease, heartbeat,
attempt count, runstep, and append-only job events.

```bash
MOLCLASS_JDBC_URL=jdbc:mysql://127.0.0.1:3306/molclass_v3 \
MOLCLASS_DB_USER=<worker-user> \
MOLCLASS_DB_PASSWORD=<secret> \
MOLCLASS_UPLOAD_ROOT=/private/molclass/uploads \
./gradlew runV3SdfWorker -PimportArgs='--once --lease-seconds 120'
```

The worker verifies the stored content length and SHA-256 before analysis. An
expired lease is returned to the queue until `maximum_attempts` is exhausted.
Analysis output is stored beside the opaque upload key and copied into
`upload_artifact.analysis_json` transactionally with terminal job state.

## Failsafe import execution

The same worker claims `SDF_IMPORT` only when no analysis job is waiting. Before
records it resolves the exact, case-sensitive property registry under the global
property-schema lock, applies only allowlisted add/widen DDL, and persists the
resolved manifest.

Each SDF record has a durable `import_record`. A successful molecule, canonical
identity lookup/insert, dataset membership, selected values, counters, and terminal
record state commit together. A molecule/property failure rolls back that unit,
then records `FAILED` and increments counters in a separate transaction. Database,
lease, storage, or upload-integrity failure stops the run for retry. Once
`failed_records * 20 > total_records`, remaining records become `NOT_PROCESSED` and
the dataset finishes `PARTIAL`.

Full InChIKey plus exact standard InChI controls canonical reuse. Failed or
conflicting canonicalization uses a salted, unmerged identity; it never merges by
name, partial key, or source identifier. The original upload remains retained and
each membership stores its source mol block independently.

## Import status API

`GET /api/v1/imports/{importRunId}` returns the durable import run, current worker runstep,
record counters, retry metadata, and at most 100 failed or not-processed record summaries.
The endpoint never returns source structures or imported property values. The persisted
`import_record` table remains the complete per-record transaction audit.
